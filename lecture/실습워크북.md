## 오늘 만들 것

리소스 9개입니다. week4와 종류도 개수도 같습니다. 달라지는 것은 그 9개가 어느 모듈 안에 들어가고, state 주소가 어떻게 바뀌는지입니다.

| 폴더 | 무엇을 하는 곳 | state 는 어디에 |
|------|--------------|--------------|
| `practice/modules/network/` | VPC + IGW + 서브넷 2 + 라우트 테이블 + 연결 2 를 **정의만** 합니다 | 없습니다 |
| `practice/modules/compute/` | 시큐리티 그룹 + EC2 를 **정의만** 합니다 | 없습니다 |
| `practice/envs/prod/` | 두 모듈을 조립해 **실제로 만듭니다**. 리소스 **9개** | **week3 의 S3 버킷** (`week05/prod/...`) |

`terraform` 명령을 치는 곳은 `practice/envs/prod` 한 곳뿐입니다. `modules/` 안에서는 `init` 도 `plan` 도 실행하지 않습니다. 그 폴더에는 `provider` 도 `backend` 도 없습니다.

> [!CAUTION]
> **비용.** `envs/prod`를 apply 하면 시간당 $0.0190이 붙습니다. destroy 를 잊고 한 달 두면 약 $13.87입니다. Block C는 선택이 아닙니다.
> `module` 블록에 `for_each`를 걸어 여러 벌 만들어보지 마세요. compute 모듈이 두 벌이면 EC2 가 2대가 됩니다. 개념워크북 14번.
>
> **올리면 안 되는 값.** 본인 공인 IP · AWS 계정번호 12자리 · 액세스 키 · `terraform.tfvars` · `terraform.tfstate` · `.pem` 파일. 마스킹 명령은 C-3에 있습니다.

> [!CAUTION]
> **공인 IP 는 화면에서 가려지고 저장소에서는 가려지지 않습니다.** `envs/prod/variables.tf` 와 `modules/compute/variables.tf` 의 `my_ip` 에 `sensitive = true` 가 붙어 있어서, plan 출력의 `ingress` 블록이 `(sensitive value)` 로 나옵니다. week4와 같습니다.
>
> 가려지는 것은 CLI 출력뿐입니다. `terraform.tfvars` 에는 평문으로 적히고 state 에도 평문으로 들어갑니다. 그래서 그 두 파일은 커밋 금지입니다. 무엇이 가려지고 무엇이 안 가려지는지는 B-6에서 직접 확인합니다.

> [!IMPORTANT]
> **오늘 폴더가 셋입니다.** `modules/network` · `modules/compute` · `envs/prod`. 파일을 여는 곳은 셋이고 명령을 치는 곳은 하나입니다.
> 이 문서의 코드블록 첫 줄에 붙은 `# pwd == ...` 주석은 **그 블록의 명령을 다 친 뒤에 있어야 하는 위치**입니다. 블록 안에 `cd`가 있으면 시작 위치는 그 위 블록의 값입니다. 매 블록 끝에 `pwd`로 대조하세요.

| 파일 | 오늘 손대나 |
|------|-----------|
| `envs/prod/versions.tf` · `providers.tf` · `variables.tf` · `locals.tf` | 읽기만 |
| `envs/prod/backend.tf` | **TODO ①** week3 버킷 이름을 손으로 |

## 오늘의 지도: 폴더 하나가 셋이 되고, 값이 문을 통해 건너갑니다

week1의 지도는 명령의 흐름, week2는 리소스 사이의 참조, week3은 state 파일이 사는 곳, week4는 값이 어디에 적혀 있는지였습니다. 오늘의 지도는 코드가 어느 폴더에 있는지와, 폴더 경계를 값이 어떻게 넘는지입니다.

### ① BEFORE: 오늘 시작 시점 (week4 가 끝난 상태)

```
 practice/
   versions.tf  providers.tf  backend.tf
   variables.tf  locals.tf  outputs.tf
   network.tf     VPC · IGW · 서브넷 x2 · 라우트 테이블 · 연결 x2
   compute.tf     시큐리티 그룹 · EC2

   폴더가 하나입니다.
   compute.tf 의 aws_instance.web 이 network.tf 의 aws_subnet.public["a"] 를
   아무 절차 없이 바로 참조합니다. 파일 이름으로 나뉘어 있을 뿐이고
   Terraform 은 이 폴더를 한 덩어리로 읽습니다.

   dev 를 만들려면 이 폴더를 통째로 복사해야 하고,
```

### [실습] A-2. TODO ①: week3 버킷을 이어 쓰고 값 채우기 (3분)

지금 하는 일은 오늘 만들 것의 state 를 week3 버킷의 새 `key` 에 두는 것입니다.

```bash
# pwd == practice/envs/prod
cd practice/envs/prod
cp example.tfvars terraform.tfvars
curl -4 ifconfig.me      # 내 공인 IP 확인
```

`terraform.tfvars`를 열어 두 줄을 본인 값으로 바꿉니다. `region` 은 그대로 둡니다.

```hcl
region       = "ap-northeast-2"
project_name = "boaz26-w5-kdh1834"
my_ip        = "1.2.3.4"
```

> [!WARNING]
> `my_ip`에 `/32`를 붙이지 마세요. compute 모듈이 `"${var.my_ip}/32"`로 조립하기 때문에, 이미 붙여두면 `1.2.3.4/32/32`가 되어 시큐리티 그룹 생성이 실패합니다.
> `terraform.tfvars`는 커밋 금지입니다. 본인 공인 IP가 들어 있습니다.

`vpc_cidr`과 `subnet_cidrs`는 `variables.tf`에 `default`가 있으니 적지 않아도 됩니다. 기본값은 이렇습니다. 맵의 **key 가 AZ 이름이고 값이 CIDR** 입니다.

```hcl
subnet_cidrs = {
  "ap-northeast-2a" = "10.0.1.0/24"
  "ap-northeast-2c" = "10.0.2.0/24"
}
```

이제 `backend.tf`를 열어 `CHANGE-ME` 두 곳을 **week3 값**으로 바꿉니다. 방금 정한 `project_name`과 다른 값입니다.

```hcl
terraform {
  backend "s3" {
    bucket         = "boaz26-w3-kdh1834-tfstate"
    key            = "week05/prod/terraform.tfstate"
    region         = "ap-northeast-2"
    dynamodb_table = "boaz26-w3-kdh1834-tflock"
    encrypt        = true
  }
}
```

> [!WARNING]
> `key`는 이미 채워져 있습니다. 건드리지 마세요. week3 리포에서 `terraform output -raw backend_config`를 복사해 오면 `key`가 `week03/app/terraform.tfstate`로 나오고, week4 코드에서 복사해 오면 `week04/app/...`으로 나옵니다. 그 줄까지 붙여넣으면 지난 주 state 를 인수합니다.
>
> `key` 의 `prod` 는 이 폴더가 `envs/prod` 라서 붙었습니다. 개념워크북 13번.

### [실습] [관찰 ✍️] B-6 (심화 ⭐). `sensitive` 가 막는 것과 고르는 근거 (2분)

지금 하는 일은 두 가지입니다. `sensitive` 의 경계를 확인하고, 서브넷을 고르는 근거를 조립하는 쪽으로 끌어올립니다.

첫째, `sensitive` 가 어디까지 막는지 봅니다. `my_ip` 에는 표시가 두 곳에 붙어 있습니다.

```bash
# pwd == practice/envs/prod
grep -A5 'variable "my_ip"' variables.tf ../../modules/compute/variables.tf
```

루트에만 붙여도 값이 모듈로 넘어갈 때 표시가 따라옵니다. 모듈 쪽에도 붙여두는 것은 이 모듈을 다른 데서 쓸 때 부르는 쪽이 표시를 잊는 경우를 대비한 것입니다.

state 는 어떤지 봅니다.

```bash
# pwd == practice/envs/prod
terraform state pull | grep -o '"cidr_blocks":[^]]*]' | head
```

본인 공인 IP 가 평문으로 보입니다. `sensitive` 가 바꾸는 것은 CLI 출력이고, 저장 쪽은 week3에서 건 버킷 암호화와 퍼블릭 접근 차단이 맡습니다. week4 개념워크북 6번.

둘째, EC2 를 어느 서브넷에 놓을지 고르는 근거를 조립하는 쪽으로 끌어올립니다. `envs/prod/main.tf`의 compute 블록에서 한 줄을 바꾸세요.

```hcl
  subnet_id = module.network.subnet_ids["ap-northeast-2a"]
```

```bash
# pwd == practice/envs/prod
terraform plan
```

```
No changes. Your infrastructure matches the configuration.
```

지금은 `public_subnet_id`가 가리키던 것과 같은 서브넷이라 아무 변화가 없습니다. 달라진 것은 **어느 서브넷을 쓰는지가 조립하는 파일에 보인다는 것**입니다. `public_subnet_id`는 `values(...)[0]`이라서 사전순 첫 key 를 지우면 가리키는 대상이 조용히 옮겨가고, 그러면 EC2 가 교체됩니다. 개념워크북 9번.

맵에 없는 key 를 적으면 어떻게 되는지도 보세요. 방금 고친 줄의 key 를 `"ap-northeast-2b"` 로 바꾸고 `plan` 을 합니다.


```

The given key does not identify an element in this collection value.
```

`module.network.subnet_ids is object with 2 attributes` 줄을 보세요. A-5 의 `module.network is object with 3 attributes` 와 같은 모양입니다. 맵에 key 가 둘뿐이라는 것을 Terraform 이 `plan` 단계에서 알기 때문에 apply 까지 가지 않고 걸립니다.

`public_subnet_id`를 쓸 때는 이런 오류가 나지 않습니다. 모듈이 알아서 하나를 골라주기 때문입니다. 오류가 나지 않는 쪽이 편하지만, 무엇을 고르고 있는지도 보이지 않습니다.

확인이 끝나면 key 를 `"ap-northeast-2a"` 로 되돌리세요.

### [실습] B-7 (심화 ⭐). `envs/dev` 로 모듈을 재사용하기

지금 하는 일은 모듈을 고치지 않고 환경을 하나 더 만드는 것입니다. **apply 는 하지 말고 `plan` 까지만** 하세요. EC2 가 두 대가 됩니다.

## 부록. 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `Error: Module not installed` | `module` 블록을 추가·삭제했는데 `init` 을 안 돌림 | `terraform init` 재실행. B-2 |
| `Error: Invalid module source address` | `source` 가 `./` 나 `../` 로 시작하지 않음 | 상대경로로 고치기. 메시지가 고칠 형태를 알려줍니다 |
| `Error: Unsupported argument` | `module` 블록에 그 모듈에 없는 인자를 넘김 | 그 모듈의 `variables.tf` 와 이름 대조 |
| `Error: Missing required argument` | `default` 없는 모듈 변수를 안 넘김 | 오류가 `module` 첫 줄을 가리킵니다. `variables.tf` 와 대조 |
| `Error: Unsupported attribute` (`module.x is object with N attributes`) | 모듈 안 리소스를 밖에서 직접 참조 | 그 모듈의 `outputs.tf` 에 output 추가. A-5 |
| `Error: Reference to undeclared resource` (모듈 안에서) | 모듈 안에서 루트의 값이나 다른 모듈을 참조 | 변수로 받기. 개념워크북 6번 |
| 모듈 안에서 `local.name_prefix` 를 못 찾음 | `locals` 는 폴더 경계를 넘지 않음 | `var.name_prefix` 로 받기 |
| `Invalid for_each argument` | `subnet_cidrs` 에 list 를 넣음 | `map(string)` 으로 넣기. week4 개념워크북 12번 |
| `Invalid index` | `subnet_ids["..."]` 의 key 가 맵에 없음 | `terraform output subnet_ids` 로 key 확인. B-6 |
| `plan` 이 7에서 멈춤 | compute 모듈 블록이 안 붙음 | B-2 확인 |
| `plan` 이 9가 아닌 이상한 숫자 | `backend.tf`의 `key`가 지난 주 것 | apply 하지 말고 `key`를 `week05/prod/...` 로 |
| `Failed to get existing workspaces: S3 bucket ... does not exist` | week3 버킷 이름 오타 또는 bootstrap 없음 | A-1로 돌아가기 |
| `Error acquiring the state lock` | 동시 실행 또는 비정상 종료 | 아무도 작업 안 하는 것 확인 후 `terraform force-unlock <LOCK_ID>` |
| `Warning: Deprecated Parameter` | `dynamodb_table` 사용 | 정상입니다. week3 개념워크북 9번 |
| `zsh: no matches found` | 주소의 대괄호를 셸이 해석 | 작은따옴표로 감싸기 |
| `destroy`가 SG/서브넷에서 멈춤 | ENI 잔존 | 잠시 후 재실행 |
